## Secure enrollment flow implemented

1. Normal world invokes TeeCredentialService::enroll_initial_pin(); the API accepts no PIN, keypad events or frame buffer.
2. The signed Provisioner TA opens the OP-TEE core Trusted UI pseudo-TA using an internal TA-to-PTA session.
3. The TUI pseudo-TA accepts only the pinned Provisioner TA UUID and asks platform secure-input/display hooks for the first PIN and confirmation. The PIN first enters a core-private Secure World buffer and is copied only into the trusted Provisioner TA memory.
4. The Provisioner TA validates numeric 6–16 digit values, compares the two entries in constant time and sends the PIN only over a secure TA-to-TA call to the Credential TA.
5. The Credential TA checks the caller UUID/login, creates the salted HMAC verifier and persistent lockout record in RPMB.
6. The normal-world launcher receives only a status result.

## Credential design

- Numeric PIN length 4–16 in Credential TA; Provisioner flow enforces at least 6 digits.
- Random 256-bit salt and TEE-held HMAC-SHA256 pepper key.
- Raw PIN is not persisted.
- Credential and pepper objects use TEE_STORAGE_PRIVATE_RPMB.
- The TA requires hardware anti-rollback protection and a protected TEE system clock; missing/weak capability, storage errors, clock rollback, malformed records or missing pepper fail closed.
- Five failures trigger persistent escalating lockout (30 seconds upward, capped at one hour); success resets failure/escalation state.
- Verification never silently recreates a missing pepper.

## Explicitly not yet production-integrated

- The Trusted UI core PTA is compiled, but its board HAL has only weak fail-closed defaults. No supported secure display or secure touch/input driver has been implemented for the QEMU reference board or a physical phone. The weak begin/read_pin/show_status/end hooks return NOT_SUPPORTED. Therefore first-time PIN enrollment is not currently usable on hardware.
- No OP-TEE Secure World/BL32 is deployed or launched by Fahim OS's current boot chain.
- No device RPMB key, RPMB secure-storage backend or TEE-protected system clock has been provisioned or tested on physical hardware.
- No production TA signing key/trust anchor is configured. CI uses the pinned OP-TEE development signing key; artifacts are not production-trusted and must be re-signed with the device owner's protected signing key and matching trust anchor.
- The native runtime is not boot-launched as a trusted Lock Screen service. The kernel QEMU role-gate test uses a synthetic LOCKSCREEN-role payload; it does not boot the native renderer or verify a real PIN.
- The runner's TEEC-enabled tests have no TEE hardware. They prove compile/link and fail-closed behavior, not secure-world invocation.

- Standards boundary: the project-specific TUI core PTA is a secure board-HAL bridge, not yet a complete GlobalPlatform TEE Trusted User Interface Low-level API v1.0.1 (GPD_SPE_055) implementation or Trusted UI PP-Module conformance claim. A production port must implement/map the secure framebuffer/input-event ownership and trusted peripheral controls required by the applicable TUI profile.
